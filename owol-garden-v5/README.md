# OWOL Garden V5 · 나의 정원 구성

V4에서 선택한 군집 수정 02의 식물·색·조명·윤곽선은 유지하고, 빈 땅부터 정원 구성을 편집하는 기능을 연결했습니다. 원본 V4 폴더와 ZIP, V2/V3/V4 저장 슬롯은 보존합니다. 이번 소스는 `owol-garden-v5`입니다.

## 실행

실행만 하려면 **OWOL-garden-v5-run.zip** 하나를 받으세요. Node.js 24가 있는 컴퓨터에서 압축을 완전히 풀고 `START-ART-WINDOWS.cmd`를 실행하거나 해당 폴더에서 다음을 실행합니다.

```sh
node serve.mjs
```

터미널에 표시된 주소를 **같은 컴퓨터**의 Chrome/Edge에서 여세요. 서버 창은 열어두세요. npm 설치, 유료 API, 외부 계정은 필요 없습니다. 실행 서버 포트는 5183입니다. 직접 HTML 더블클릭, 실제 Windows 실행기, Safari와 실제 휴대폰은 미검증입니다.

소스 ZIP에는 수정용 `src/`와 빌드·테스트·검증 자료가 있습니다. 이미 포함한 `dist/`를 실행하려면 `node scripts/serve.mjs`를 사용합니다(포트 5182). 개발 시:

```sh
npm ci
npm run dev
npm run package
```

캐시 권한이 제한된 클라우드에서는 `npm ci --cache /tmp/owol-v5-npm`을 사용합니다. 원본 V4와 포트·폴더·저장 키가 다릅니다. 단일 HTML 서버는 시작할 때 파일을 읽으므로 다시 패키징한 뒤에는 이전 서버를 종료하고 재시작하세요.

## 시작과 땅

- **이 정원 바꿔보기**: V4 기준 6 × 4.5 m, 식물 18개와 벤치 1개에서 시작합니다.
- **빈 땅부터 만들기 / 새 빈 땅**: 흙 바닥과 경계만 생성합니다. 건물·벽·화단·포장·식물·가구는 0개입니다.
- **기본 구성**: 빈 땅, 앞마당, 뒷마당, 옆마당, ㄱ자 집, ㄷ자 집, 잔디 중심, 식재 중심, 데크, 옥상 등 10개의 실제 평면 구성을 고릅니다. `예시 식물도 함께 가져오기`를 해제하면 구조만 가져옵니다.
- **땅 크기**: 자유 부지는 가로·세로 3–16 m입니다. 중심을 유지하며 경계를 바꿉니다. 식물·건물의 좌표와 크기를 몰래 확대하지 않습니다. 잘리는 면적과 이동 대기 수를 적용 전에 확인합니다. 건물이 경계 밖이면 적용할 수 없습니다.
- **배치만 비우기**는 개별 식물·소품·디딤석만 비우며, 구성 면과 건물은 남깁니다. 새 빈 땅과 구분됩니다.

고정 벽·난간이 있는 기존 공간을 자유 구성으로 가져온 뒤에는 그 치수를 직접 변경하지 않습니다. 기본 구성 카드에서 원하는 치수로 새로 시작하거나, 자유 부지에서 구성하세요. 옥상의 실제 하중·방수·난간 안전은 검증하지 않습니다.

## 화단과 바닥

1. `화단과 바닥`을 누르고 `새 면`을 선택합니다. 종류는 노지 화단·잔디·면 포장·독립 플랜터입니다.
2. 사각형/원형, 0.5/1/2 m 브러시로 클릭하거나 드래그합니다. 빠른 드래그도 중간을 보간합니다.
3. `면 선택`으로 고른 영역만 `늘리기`·`줄이기` 합니다. 중앙을 지우면 실제 구멍이 생깁니다. 연결부를 지우면 분리된 섬이 됩니다. 분리된 섬은 같은 논리 영역 ID 안에서 함께 선택됩니다.
4. 면 종류 전환, 모서리 다듬기, 전체 이동·복제·삭제, 같은 설정의 면을 명시적으로 합치기를 지원합니다. 다른 영역은 자동으로 바꾸거나 합치지 않습니다.
5. 식물은 적용 전까지 원본에 남습니다. `유지 / 이동 대기` 수를 확인하고 **변경 적용**합니다. 배치 불가능해진 식물·소품은 ID·좌표·회전·크기·모델 참조를 유지하여 대기함으로 갑니다.

편집 중 `획 되돌리기`는 드래그 한 번 단위입니다. 적용한 뒤 일반 되돌리기 한 번은 면·식물·대기함을 함께 복원합니다. 카메라 전환, blur, Escape, pointercancel, 두 번째 손가락은 **진행 중인 획만** 취소하고 완료한 획은 유지합니다. 세션 전체를 버리려면 명시적인 `취소`를 누르세요. 미적용 편집은 저장되지 않습니다.

우드래그/중드래그/휠 카메라는 유지했습니다. 큰 구성으로 바꾼 뒤 화면에 잘리면 오른쪽 집 모양(전체 보기) 버튼으로 맞추세요. 모바일에서 한 손가락은 현재 편집 도구가 소유하고 카메라는 `둘러보기`에서 조작합니다. `접기`로 패널을 줄일 수 있습니다. 격자와 미리보기는 PNG에 포함되지 않습니다.

최대 면+플랜터 48개, 전체 4096점, 한 ring 1024점의 안전 제한이 있습니다. 정리한 multipolygon과 holes를 렌더·면적·포함 판정·저장에 공통 사용합니다. 모서리 다듬기는 실제 윤곽 변경이며 원래 윤곽으로 돌아가려면 되돌리기를 사용합니다. 고급 꼭짓점 편집은 기존 V4 윤곽에서 계속 사용할 수 있고, 새 패치 면의 꼭짓점 편집은 제공하지 않습니다.

## 포장과 집

면 포장은 재료(석재·자갈·콘크리트 계열·목재)와 패턴(정형·부정형·연속·블록·판재)을 따로 저장합니다. 조합 카드, 90도 방향 전환, 미터 단위 모듈 크기를 사용하세요. 패턴은 실제 면 mesh에 그려져 외곽과 구멍에서 잘립니다. 부정형 seed는 저장되며 프레임마다 무작위로 바뀌지 않습니다. `개별 포장`의 디딤석·목재·자갈 도구도 남아 있습니다.

`집 모양`에서는 최대 3개의 단순 네모/L/U 볼륨을 추가하고 위치·치수·날개·높이·90도 회전·반전과 벽에 붙은 문의 위치를 바꿉니다. 안쪽 마당 치수는 외곽과 날개 치수에서 계산하여 표시합니다. 형태 변경 시 문을 새 벽에 놓는 내용을 확인합니다. 건물 아래 원래 면은 숨겨 보존하며, 건물을 삭제·이동하면 다시 보입니다. 문 앞은 비우고 면적은 건물과 중복 합산하지 않습니다.

연결 경로는 footprint와 가이드 폭을 고려한 0.25 m 격자 검사입니다. 끊긴 길은 경고하며 자동으로 길을 영구 고정하지 않습니다. 실제 건축·소방·접근성 법규 판단, 실내, 자유 보행, 건물 모서리를 잡는 CAD 편집은 없습니다. 건물 이동은 수치 입력 방식입니다. 고정 데크/옥상 조건에서는 자유 건물 편집을 제한합니다.

## 식물과 저장

교목·관목·초본, 이름 검색, 잎 색·꽃 색·잎의 결·모델 높이의 교집합 필터가 동작합니다. 상세 정보는 형태 예시와 미확인 식물 정보를 구분합니다. 기존 7개 형태의 데이터를 정리했으며, 현재 V4 카툰 프로필에서 배치 가능한 형태는 기존 4개입니다. 나머지 3개는 V3 전용으로 명시합니다. **새 식물 모델 0개, 검증된 품종 DB 0개**입니다. 실제 과·속·구근성·상록성·성숙 크기·생육 적합성을 임의 생성하지 않았습니다.

- 수동 저장: `owol-garden-composition-v5`
- 확정 작업의 최근 복구: `owol-garden-composition-v5-recovery`
- 별도 저장: 같은 접두사의 `-archive-…`

새로 열면 최신 유효 V5 저장 또는 복구 기록을 읽습니다. 빈 땅과 확정된 구성도 복원하므로 예시 식물이 자동으로 생기지 않습니다. 미적용 획과 무효 preview는 복구 슬롯에 쓰지 않습니다. 원래 V2/V3/V4 키는 덮어쓰지 않습니다. V2는 원래 8 × 8 공간, V3/V4는 기존 조건과 제어점을 보존하여 가져옵니다. 기존 겹친 바닥을 새 패치 편집으로 전환할 때만 명시적인 편집 적용을 통해 한 면 소유 구조로 정리합니다.

저장 공간 오류는 현재 정원을 유지하고 안내합니다. 브라우저·주소가 바뀌면 저장소가 다릅니다. 컴퓨터를 옮길 때 **JSON ↓ / JSON ↑**를 사용하세요. 취향 보드에는 실제 구성 이미지와 식재·잔디·포장·건물 면적이 포함됩니다. 개인정보·회원가입·결제·상담 전송·분석 추적기는 없습니다.

## 검증 자료

`VALIDATION.md`에 이번 실제 검사 결과와 성능 조건, `ASSETS.md`에 출처, `review.html`에 실제 캡처가 있습니다. `examples/`에는 빈 땅·패치/포장·L/U형 건물의 V5 저장 예시가 있습니다.

```sh
node --test tests/scene.test.mjs tests/zone-foundation.test.mjs tests/zones.test.mjs tests/composition.test.mjs
OWOL_TEST_URL=http://127.0.0.1:5183 npm test
```

테스트 설정은 Linux Chromium `/usr/bin/chromium`과 SwiftShader를 사용합니다. 실기기 성능 보장은 아닙니다. 실제 식재와 시공은 현장 조건과 전문가 검토가 필요합니다.
